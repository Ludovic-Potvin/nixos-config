# Repo structure

Single-host NixOS flake for host `spidermonkey`, using home-manager as a NixOS module (not standalone).

## Layout

```
flake.nix                      # inputs + nixosConfigurations.spidermonkey
hosts/spidermonkey/
  default.nix                  # host entrypoint: imports modules/*, sets hostName, stateVersion, wires home-manager
  hardware-configuration.nix   # generated by nixos-generate-config — do not hand-edit
modules/
  system/                      # default.nix imports boot.nix, networking.nix, locale.nix, users.nix
  desktop/                     # default.nix imports hyprland.nix, greetd.nix
  programs/                    # default.nix — flat list of system-wide programs/packages (no submodules)
home/lpotvin/
  default.nix                  # home-manager entrypoint: imports applications.nix, noctalia.nix, noctalia homeModule
  applications.nix             # dotfile linking only (xdg.configFile / home.file), no program options
  noctalia.nix                 # programs.noctalia home-manager options
  hyprland/, fish/, kitty/, nvim/, noctalia/, tmux/, wallpaper/   # actual dotfiles symlinked by applications.nix
```

## Conventions

- Every `modules/<area>/default.nix` is a pure import list — area-specific options live in sibling files, not in `default.nix`.
- System-level options (`services.*`, `programs.*enable`, `environment.systemPackages` for system-wide tools) go in `modules/`.
- User-level/home-manager options (dotfiles, `programs.noctalia` home settings) go in `home/lpotvin/`.
- `modules/programs/default.nix` is the exception to the "options live in sibling files" rule — it's a flat grab-bag of system packages + simple `programs.*.enable` toggles. Split it out if it grows unwieldy.
- Dotfiles are symlinked via home-manager (`xdg.configFile."<app>".source = ./app`), not hand-copied — edit the files under `home/lpotvin/<app>/` and they take effect on next `home-manager`/`nixos-rebuild switch`.

## Flake inputs

- `nixpkgs` pinned to `nixos-26.05`.
- `home-manager` pinned to `release-26.05`, follows the same nixpkgs.
- `noctalia` (github:noctalia-dev/noctalia) — provides `homeModules.default` (used in `home/lpotvin/default.nix`) for `programs.noctalia` (the shell/bar). It does **not** provide a greeter — the greeter is the separate `noctalia-greeter` package already in nixpkgs, wired manually via `services.greetd` in `modules/desktop/greetd.nix` (nixpkgs pin as of writing has no dedicated `services.displayManager.noctalia-greeter` option yet, only `dms-greeter`).

## Desktop session flow

`services.greetd` (modules/desktop/greetd.nix) launches `noctalia-greeter-session` as the `greeter` user. That binary runs its own self-contained wlroots compositor just for the login UI (independent of Hyprland), then on login hands off via greetd to whichever session the user picks. `programs.hyprland.withUWSM = true` (modules/desktop/hyprland.nix) auto-generates the `wayland-sessions/hyprland-uwsm.desktop` entry that the greeter's session picker discovers — no extra wiring needed to connect the two.

## Things to know

- `configuration.nix` at the repo root was a leftover from the original `nixos-generate-config` install; it was never imported by the flake and has been deleted. The real entrypoint is `hosts/spidermonkey/default.nix`.
- To validate a change without applying it: `nix build .#nixosConfigurations.spidermonkey.config.system.build.toplevel --no-link`. Note the flake reads from the git index, so new files must be `git add`ed (even if uncommitted) before the build will see them.
- To apply: `sudo nixos-rebuild switch --flake .` (or `boot` to apply on next boot).
